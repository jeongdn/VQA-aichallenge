## 2. 공통 기준
- **검증셋**: train에서 정답 글자별 250개씩 뽑은 고정 1,000문항 (SEED 42, md5 `df05e4bc19d27ebceeef2570672149c2`). 학습 5,714 / 검증 1,000. 평가 해상도 up2.0.
- **판정**: 같은 문항끼리 비교(고침 / 새로 틀림 / 순이득). 규칙은 결과를 보기 전에 고정.
  - E1~E5 규칙: 앙상블에서 Q35 자리만 바꿨을 때 +3 이상(새로 틀림 ≤ 고침/2)이면 채택 후보, +1~+2면 공개 확인, 0 이하면 불채택.
- **공개 점수**: 문항 수 = round(점수 × 3,357). 표시 점수는 소수 5자리에서 버림.
- **지금 제출 레시피** (참고. E14부터는 이 레시피를 기준으로 삼지 않음)
  - `clean4_qg_hcx` = Q35·Q38·GDEV·G·HCX 확률 평균, 가중치 1·1·1·1·2. 검증 97.7% (오답 23). 공개 0.97646 (팀 확인. E시리즈 원본 문서의 0.97636은 잘못 적힌 값).
  - `ens_q38_gemma4` = Q38+G.
  - `ens_q38_gdev_cal` = Q38+GDEV, 멤버별 온도 보정(T70 격자).
  - `majority_vote` = 위 셋의 다수결. 공개 0.97676.
- **학습 공통**
  - LoRA r16 / α32 / dropout 0.05, 유효 배치 16 (2×8), cosine + warmup 5%, 선지 셔플, 학습 해상도 native(Gemma는 up2.0), 정답 글자 토큰 CE.
  - 27B 이상은 `USE_4BIT="auto"` 정규식 규칙 때문에 NF4로 학습됨(비전 타워 제외). E8 `_full`과 E13은 bf16.

## 9. 발표·최종 문서에 쓸 교훈
- **검증셋이 작았음**: 1,000문항(오답 20여 개)으로는 ±3문항 차이를 우연과 구별하기 어려움. 학습은 3,500문항이면 충분했으므로 절반을 검증에 쓰거나 2-fold 교차 예측으로 6,714문항 전체를 검증에 쓰는 설계가 나았음.
- **같은 문항 비교 + 결과를 보기 전에 고정한 판정 규칙**: 단독으로 좋아 보인 변형(E4 aux20 97.6%)을 걸러냈고, 공개만 보고 채택했다 떨어지는 일을 줄임.
- **공개 최고 점수는 부풀려짐**: 여러 제출 중 최고를 고르면 실제보다 높음. 새 후보가 몇 문항 낮게 나와도 실력이 낮다는 뜻이 아님 (E8·E9·E15 모두 −2~−7).
- **검증으로 조합을 고를 때는 절차를 평가**: 중첩 교차검증 + 1-표준오차 규칙. 조합을 많이 시험해 검증 1등을 고르면 그 1등은 대부분 운.
- **천장은 라벨 노이즈와 같은 오답을 확신하는 구조가 정함**: 단독 성능 향상이 곧 앙상블 향상은 아님. 이득은 의견이 갈리는 문항에서만 나옴.
- **정밀도(4bit NF4 vs bf16)는 이 과제에서 병목이 아니었음**: 같은 시드면 99% 같은 답.
